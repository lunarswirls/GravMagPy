# Equivalent-source solutions and GeoTIFF context maps

The map tools display equivalent-source fields alongside georeferenced spectral, reflectance, topography, or magnetic products. Panels share longitude/latitude bounds and have individually labeled color scales with configurable colormaps and ranges. The GeoTIFF's projection and affine transform determine its position; image-array dimensions are not treated as geographic coordinates.

## Dependencies and example

Map tools are optional and require Rasterio and Matplotlib. Install them in the selected virtual environment:

```bash
/Users/danywaller/code/venvs/gravmagpy/bin/python -m pip install -e '.[maps]'
PYTHONPATH=src /Users/danywaller/code/venvs/gravmagpy/bin/python examples/lpmag/plot_equivalent_geotiffs.py
```

The example uses `wake_dir/output/equivalent_wake/dipoles.csv`, generated by `equivalent_wake.py`, and configured local LROC WAC and Hood 30 km magnetic-model GeoTIFFs. It produces a four-panel overview and a six-panel Bx/By/Bz/Btot comparison under `wake_dir/figs/equivalent_geotiffs/`. `wake_dir` is the CSV directory described in the architecture's [LPMAG reference workflow](architecture.md#lpmag-reference-workflow). Map settings and paths are editable lowercase variables; the script does not modify the input CSVs or GeoTIFFs. Set `source_path` to select a different saved solution.

Add LAMP or UV-ratio GeoTIFFs to the example's `rasters` list using the dictionary format below. Raster files must be available at the configured paths.

## Plot a saved or in-memory solution

```python
from gravmagpy.maps import plot_equivalent_maps

rasters = [
    {"path": "/path/to/lamp_reflectance.tif", "title": "LAMP reflectance",
     "unit": "reflectance", "cmap": "viridis", "vmin": 0.01, "vmax": 0.045},
    {"path": "/path/to/wac_ratio.tif", "title": "WAC 321/415 nm",
     "unit": "ratio", "cmap": "gray", "vmin": 0.685, "vmax": 0.75},
]
plot_equivalent_maps(
    "dipoles.csv", rasters, "figs/equivalent_context.png",
    bounds=(-62, 2, -54, 14), altitude_km=30, shape=(241, 241),
    components=("btot",), source_layer=1,
)
```

The solution may be a `fit_equivalent_sources` result, a source DataFrame, or a saved `dipoles.csv`. The required columns are `lat_deg`, `lon_deg`, `radius_m`, `mx_am2`, `my_am2`, and `mz_am2`. Moments are planet-fixed Cartesian A m², not magnetization in A/m. The API accepts equivalent point-dipole solutions, not nonlinear block-fit `sources.csv` files.

Omit the image path to use the source CSV's owning case directory and `figs/<source-stem>_context_<altitude>km.png`. An in-memory solution without a saved source path requires an explicit image path. See [output path conventions](output_paths.md).

Bounds are `(west, south, east, north)` in degrees. Shape is `(rows, columns)`. A crossing such as `(170, -10, -170, 10)` is displayed as continuous longitude 170–190 with wrapped tick labels. Maps are regional, with a maximum longitude span of 180 degrees. The display uses a geographic grid and an aspect correction at the central latitude, not a polar map projection.

Components can select any of `bx`, `by`, `bz`, and `btot`. The optional source panel shows moment magnitude and depth for `source_layer` (default 1). Cyan circles mark that layer's source positions projected onto the surface. **All source layers contribute to predicted fields and contours**, regardless of the displayed layer. Set `show_source_panel=False`, `show_sources=False`, or `contours=False` independently. White contours on context panels are the predicted Btot in nT at the selected altitude.

Color limits default to each panel's 2nd/98th percentiles; signed field components use symmetric limits and Btot/moment magnitudes start at zero. Raster dictionaries can specify `vmin`/`vmax` explicitly. Color scales are intentionally independent across different physical quantities. A spectral ratio, surface field, and 30 km field must not be interpreted as measurements of the same quantity or altitude merely because they share an extent.

## Predict at a new altitude

```python
from gravmagpy import equivalent_field_grid, predict_equivalent_field

grid = equivalent_field_grid("dipoles.csv", bounds=(-108, -28, -102, -22),
                             altitude_km=30, shape=(181, 181), radius_km=1737.4)
bx, by, bz, btot = (grid[key] for key in ("bx_nt", "by_nt", "bz_nt", "btot_nt"))
field = predict_equivalent_field(xyz_km, "dipoles.csv", radius_km=1737.4)
```

Field evaluation uses a double-precision C-callable Fortran dipole kernel in `orbital.f90`, with the same dipole formula and moment units as the equivalent-grid fitter. It evaluates the fitted sources at the requested positions; it does not interpolate observations collected at different altitudes into a constant-altitude map.

Grid arrays are north-up: the first row is the northernmost pixel center, and longitude increases across columns. `bounds` are pixel edges. The source result supplies the reference radius when available; CSVs default to lunar radius 1737.4 km unless explicitly overridden. Surface predictions (`altitude_km=0`) are supported, but a coincident source/observation point raises an error. Downward continuation can amplify poorly constrained short-wavelength structure and is conditional on the fitted equivalent-source model, not proof of resolved subsurface geometry.

## Read georeferenced data independently

```python
from gravmagpy.maps import read_geotiff

raster = read_geotiff("map.tif", bounds=(-108, -28, -102, -22), shape=(241, 241),
                      band=1, resampling="bilinear", radius_km=1737.4)
values = raster["data"]
```

`read_geotiff` reads a padded regional window, preserves the dataset's validity mask/nodata, and reprojects it onto the requested geographic pixel grid. This follows Rasterio's [windowed reading](https://rasterio.readthedocs.io/en/stable/topics/windowed-rw.html) and [reprojection](https://rasterio.readthedocs.io/en/stable/topics/reproject.html) APIs. Invalid pixels remain masked; they are not replaced by meaningful zero values. Explicit masks are read before reprojection to avoid losing them in a virtual-warp conversion. See Rasterio's [mask conventions](https://rasterio.readthedocs.io/en/stable/topics/masks.html).

Projected, rotated, and geographic affine GeoTIFFs are supported, including 0–360 and −180–180 longitude rasters. `geographic_crs(radius_km)` constructs a spherical planetary CRS; lunar data are not silently relabeled WGS84. An absent CRS or an incompatible celestial-body radius raises an error. Supply `source_crs` only when the file's metadata are known to be missing or incorrect. GCP/RPC-only imagery should first be orthorectified into an affine GeoTIFF.

Band scale and offset metadata are applied by default; explicit `scale`/`offset` replace those values. Optional `nodata` adds another invalid-value code without reviving existing masked pixels. `nearest`, `bilinear`, `cubic`, and `average` resampling are available; use `nearest` for categorical maps. These reader settings can also be supplied in each raster dictionary passed to the plotting function.

The output grid is limited to four million pixels and each source window to sixteen million pixels. Use a smaller region or a downsampled GeoTIFF if the source window exceeds that limit. Missing files, empty overlap, invalid band numbers, and misspelled raster settings raise explicit errors.
